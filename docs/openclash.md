# OpenClash 使用说明

## 两种链接

- **原始订阅 `/raw/<密钥>`**：返回最后一次通过校验的机场原始订阅字节。机场短暂失败时继续返回旧缓存；首次尚无有效缓存时返回 503。
- **转换订阅 `/clash/<密钥>`**：调用配置好的在线转换服务，返回包含 `proxy-providers` 的 Mihomo/OpenClash 配置。全局转换和该分享记录的转换权限都必须开启。

在线转换会把本服务生成的 `/raw/<密钥>` 地址发送给转换服务，但不会发送机场真实订阅 URL、机场账号或管理员密码。转换失败时会使用该分享最后一次有效的脱敏模板；从未成功时返回 503。

## 添加到 OpenClash

1. 登录本服务 WebUI 的“分享链接”页面。
2. 新建仅供这台 OpenClash 使用的独立记录；默认有效期为 365 天。
3. 需要在线转换时，同时开启“允许 OpenClash 转换”。原始权限会被自动开启，因为转换配置必须引用原始链接。
4. 创建后立即复制所需链接。完整密钥只在创建或轮换时显示一次。
5. 在 OpenClash 的订阅管理中粘贴该 URL，并按需设置 OpenClash 自己的更新周期。

转换结果使用 `proxy-providers` 引用同一条原始订阅，因此 OpenClash 拉取转换配置后仍会按 provider 配置更新节点。不要把这两种链接误认为两个独立的安全权限。

## 到期、撤销与轮换

- 到期或撤销后，链接会立即统一返回 404；
- 续期保留现有密钥，但不会解除已撤销状态；
- 轮换会让旧链接立即失效，并只显示一次新链接；
- 删除记录不可恢复。

建议为每台路由器或每位朋友创建独立记录，这样可以单独撤销而不影响其他客户端。

## 缓存状态

上游刷新只有在 HTTP、大小、格式和节点校验全部通过后才替换缓存。失败时：

- 已有有效缓存：继续提供缓存，WebUI 显示 stale、失败原因和连续失败次数；
- 没有有效缓存：订阅接口返回 503，不会把登录页或 Cloudflare 验证页交给 OpenClash；
- 失败响应不会覆盖最后一次有效文件。

## 机场永久轮换 Token

如果机场将来永久作废真实订阅 Token，本项目不会绕过网页验证自动领取新 Token。取得新的真实订阅 URL 后：

1. 修改未纳入版本控制的 `secrets/upstream_url`；
2. 执行 `docker compose up -d --force-recreate`，让应用在启动时重新读取 Secret；
3. 在 WebUI 手动刷新并确认成功。

旧的有效缓存会保留到新上游成功通过校验，不会因为一次失败而被清空。

## 修改 Base URL

数据库只保存分享密钥哈希，无法恢复或批量改写已经复制出去的完整链接。LAN 或公网 Base URL 发生变化时有两种处理方式：

1. 让使用者只替换已保存 URL 的 origin，保留 `/raw/<密钥>` 或 `/clash/<密钥>` 路径不变；
2. 在 WebUI 中逐条轮换密钥并重新分发新链接。

公网链接必须使用 Lucky 提供的 HTTPS origin；在 Lucky 证书和反向代理完成前不要开启公网模式。
